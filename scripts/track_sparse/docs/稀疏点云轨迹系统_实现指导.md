# 多相机多帧稀疏点云轨迹系统实现指导

## 1. 项目目标

本项目目标不是简单地对相邻帧的三维稀疏点云执行最近邻匹配，而是构建一个稳定的：

> **Multi-view Spatio-Temporal Feature Tracking + Re-triangulation System**

核心思想：

1. 使用已知多相机内参、外参建立相机几何关系。
2. 在同一时刻通过跨相机特征匹配建立空间对应关系。
3. 在同一相机不同时间之间通过特征匹配和光流建立时间对应关系。
4. 将空间边和时间边融合为长期二维 Observation Track。
5. 为每个长期轨迹分配稳定的 `track_id`。
6. 每一帧根据该 `track_id` 当前时刻的多视角二维观测重新三角化三维坐标。
7. 使用原有逐帧稀疏点云、重投影误差、多视角一致性和时间运动一致性进行验证。
8. 支持新轨迹出生、遮挡、恢复、长期丢失和轨迹终止。
9. 最终输出带长期身份 ID 的时序三维稀疏点云，为 4DGS 动态建模提供监督。

最终希望得到：

```text
Track 001:
t0 -> X0
t1 -> X1
t2 -> X2
t3 -> X3
...

Track 002:
t0 -> X0
t1 -> X1
t2 -> OCCLUDED
t3 -> X3
...

Track 003:
t5 -> X5
t6 -> X6
...
```

轨迹的数学形式：

\[
Track_i = \{(t,\mathbf X_i^t,C_i^t,V_i^t,S_i^t)\}_{t=t_s}^{t_e}
\]

其中：

- `i`：长期 Track ID。
- `t`：帧编号。
- `X_i^t`：该轨迹在第 t 帧的三维位置。
- `C_i^t`：置信度。
- `V_i^t`：可见性。
- `S_i^t`：轨迹状态。

# 2. 输入与内置预处理

当前实现的首选输入是原始同步多相机视频。用户不需要先运行其他流水线：

```text
<input>/
├── cam00.mp4
├── cam01.mp4
├── ...
└── poses_bounds.npy              # 可选旁路信息
```

`scripts/track_sparse/run.py` 会先执行：

1. 各路视频同步抽帧并规范化为 `camXXX/camXXXframeYYY.png`。
2. 没有已知标定时，用所有相机第一帧执行 COLMAP SfM，估计固定内外参。
3. 对每台相机的全部帧应用固定去畸变映射。
4. 生成内部固定参考模型 `calibration/reference_sparse/0`。
5. 将去畸变图和固定标定直接交给后续时空轨迹模块。

已有去畸变图像与固定 COLMAP 标定仍作为高级兼容输入支持。

每个相机至少需要：

```text

```

内部统一表示为：

\[
K_c =
\begin{bmatrix}
f_x & 0 & c_x\\
0 & f_y & c_y\\
0 & 0 & 1
\end{bmatrix}
\]

## 2.3 相机外参

固定相机系统默认：

\[
P_c = K_c[R_c|t_c]
\]

所有帧共用相同相机外参。

必须明确代码内部外参约定：

```text
world_to_camera
```

或：

```text
camera_to_world
```

项目内部统一采用一种约定，禁止混用。

推荐内部统一：

```text
world_to_camera:
X_cam = R * X_world + t
```

例如：

```text
data/
└── sparse_per_frame/

    ├── 000002.ply
```

原有稀疏点云主要用途：

5. 新生轨迹验证。
6. 后续 4DGS spawn anchor。

**不要将逐帧点云最近邻作为主 Track ID 传播方式。**

# 4. 核心设计原则

Agent 实现时必须遵守以下原则。

## 原则 1：Track ID 属于物理点身份，而不是某一帧的 point3D_id

错误：

```text
frame 0 point3D_id=125
frame 1 point3D_id=401

=> 两个不同点
```

实际可能是同一个真实表面点。

因此需要新的全局：

```text
global_track_id
```

---

## 原则 2：Track 身份主要通过二维时空观测传播

核心链路：

```text
2D observation
    ↓
temporal correspondence
    ↓
track_id
    ↓
multi-view triangulation
    ↓
3D position
```

而不是：

```text
3D point
    ↓
nearest neighbor
    ↓
3D point
```

---

## 原则 3：三维坐标每一帧重新三角化

对于：

```text
track_id = 102
```

第 t 帧：

```text
cam01 -> (u1,v1)
cam03 -> (u3,v3)
cam04 -> (u4,v4)
```

计算：

\[
X_{102}^t =
Triangulate(P_1,p_1,P_3,p_3,P_4,p_4)
\]

下一帧重新使用当前二维观测：

\[
X_{102}^{t+1}
\]

不要简单使用：

```text
X(t+1) = X(t) + estimated_3D_flow
```

---

## 原则 4：多相机共同投票决定身份

不能让单相机错误直接改变 Track ID。

例如：

```text
cam01 : A_t -> A_t+1
cam02 : A_t -> A_t+1
cam03 : A_t -> B_t+1
cam04 : A_t -> A_t+1
```

最终使用多数和置信度加权判断：

```text
A remains Track A
```

---

## 原则 5：错误候选优先进入 uncertain，而不是直接删除

轨迹系统必须避免过度激进。

特别是：

- 人体手臂。
- 手。
- 衣物边缘。
- 遮挡区域。
- 快速运动区域。
- 低纹理区域。

都可能暂时失配。

# 6. Step 1：相机图 Camera Graph

## 6.1 为什么需要 Camera Graph

假设 N 个相机。

如果全部两两匹配：

\[
O(N^2)
\]

36 台相机：

\[
C_{36}^{2}=630
\]

每一帧都进行全部 pair 匹配没有必要。

应该根据相机真实几何关系建立：

```text
camera graph
```

---

## 6.2 Camera Graph 边的判断

对于相机 i 和 j，计算：

### 1. 相机中心距离

\[
d_{ij} = \|C_i-C_j\|
\]

### 2. 光轴夹角

\[
\theta_{ij}
=
\arccos
(
d_i^T d_j
)
\]

### 3. 视锥重叠

推荐方法：

在合理场景深度范围：

```text
depth_min
depth_max
```

从相机 i 图像均匀采样像素，例如：

```text
16 x 9
```

将采样射线投到多个深度 plane：

```text
depth = [d1,d2,d3,...]
```

得到世界坐标点，再投影到相机 j。

统计：

```text
valid_projection_ratio
```

近似视锥重叠率：

\[
O_{ij}
=
\frac{N_{visible}}{N_{sample}}
\]

---

## 6.3 Camera Edge Score

例如：

\[
S_{ij}
=
w_o O_{ij}
+
w_a S_{angle}
+
w_b S_{baseline}
\]

保留：

```text
score > threshold
```

或者每个相机保留 Top-K 邻居。

推荐：

```yaml
camera_graph:
  top_k: 6
  min_overlap: 0.10
  max_view_angle_deg: 100
```

输出：

```json
{
  "cam_000": ["cam_001", "cam_002", "cam_035"],
  "cam_001": ["cam_000", "cam_002", "cam_003"]
}
```

# 8. Step 3：同帧跨相机 Spatial Matching

对于：

```text
frame = t
```

只对 Camera Graph 中相邻相机执行：

```text
cam_i(t) <-> cam_j(t)
```

---

## 8.1 匹配模型

第一版推荐：

```text
LightGlue
```

第二阶段可加入：

```text
RoMa
```

补充低纹理和大视角变化区域。

---

## 8.2 必须进行几何验证

因为内外参已知，可以直接使用极线约束。

对于匹配点：

\[
x_j^T F_{ji}x_i \approx 0
\]

其中：

\[
F_{ji}
=
K_j^{-T}
[t_{ji}]_\times
R_{ji}
K_i^{-1}
\]

过滤：

```text
epipolar_error < threshold
```

建议：

```yaml
spatial_matching:
  epipolar_threshold_px: 1.5
```

---

## 8.3 三角化验证

对于候选 match：

```text
cam_i -> p_i
cam_j -> p_j
```

三角化：

\[
X
\]

要求：

1. 正深度。
2. 重投影误差小。
3. 三角化角足够大。

例如：

```yaml
triangulation:
  min_angle_deg: 1.0
  max_reproj_error_px: 2.0
```

# 9. Step 4：形成同帧 Multi-view Observation

如果：

```text
cam01:f10 <-> cam02:f32
cam02:f32 <-> cam04:f81
```

应该合并成：

```text
SpatialObservationGroup #125

cam01:f10
cam02:f32
cam04:f81
```

可以使用：

```text
Union-Find / Disjoint Set
```

但合并时必须检查：

> 同一个 group 中同一 camera 不能出现两个不同 feature。

如发生冲突，按：

```text
matching score
epipolar error
reprojection error
```

进行选择。

# 10. Step 5：同相机跨帧 Temporal Matching

这是 Track ID 长期传播的关键模块。

对于每个相机：

```text
cam_i(t)
   ↓
cam_i(t+1)
```

建立时间边。

推荐第一版：

```text
LightGlue temporal matching
+
Optical Flow
```

---

# 11. Temporal Matching 双路径

## 11.1 路径 A：Feature Temporal Matching

```text
frame_t
   ↓
features
   ↓
LightGlue
   ↓
frame_t+1
```

适合：

- 大运动。
- 纹理明显区域。
- 遮挡后重新关联。
- 长周期识别。

---

## 11.2 路径 B：Optical Flow

推荐可选模型：

```text
SEA-RAFT
RAFT
GMFlow
FlowFormer++
```

对于：

\[
p_t
\]

光流：

\[
F_{t\rightarrow t+1}(p_t)
\]

预测：

\[
p_{t+1}^{flow}
=
p_t + F_{t\rightarrow t+1}(p_t)
\]

---

## 11.3 Forward-Backward Check

计算：

```text
t -> t+1
t+1 -> t
```

要求：

\[
\|
F_{t\rightarrow t+1}(p_t)
+
F_{t+1\rightarrow t}(p_{t+1})
\|
<\tau_{fb}
\]

这样可以剔除遮挡和错误 flow。

---

# 12. Feature + Flow 融合

设：

```text
feature prediction = p_feature
flow prediction    = p_flow
```

定义：

\[
d =
\|p_{feature}-p_{flow}\|
\]

例如：

```text
d < 2 px
```

认为非常可靠。

```text
2 px < d < 5 px
```

认为一般可靠。

```text
d > 5 px
```

进入 uncertain。

Temporal Match Score 可以定义：

\[
C_{temp}
=
w_mC_{match}
+
w_fC_{flow}
+
w_{fb}C_{fb}
\]

---

# 13. Temporal Matching 不应只做 t -> t+1

第一版至少支持：

```text
t -> t+1
```

增强版加入：

```text
t -> t+2
t -> t+3
```

主要用于：

- t+1 遮挡。
- 模糊。
- 临时失配。

配置：

```yaml
temporal:
  offsets: [1, 2]
```

不要一开始设置很大的时间跨度。

```text

```

## Spatial Edge

```text

```


## Temporal Edge

```text

```

```text

```

# 17. 多相机时间投票

假设第 t 帧 Track A：

```text
cam01 -> feature A1
cam02 -> feature A2
cam05 -> feature A5
```

到 t+1：

```text
cam01: A1 -> B1
cam02: A2 -> B2
cam05: A5 -> C5
```

如果：

```text
B1 和 B2 属于同一个 t+1 SpatialGroup B
```

则：

```text
A -> B
```

获得两票。

定义：

\[
Vote(A\rightarrow B)
=
\sum_{c\in cameras}
w_c
\]

要求：

```yaml
association:
  min_camera_votes: 2
```

必要时允许单相机极高置信度候选进入 tentative，但不要直接 ACTIVE。

---

# 18. Step 8：每帧重新三角化 Track

对于 Track i 在帧 t：

```text
observations:
cam_01 -> p1
cam_03 -> p3
cam_04 -> p4
cam_07 -> p7
```

使用 robust multi-view triangulation。

---

## 18.1 第一版

可使用线性 DLT。

---

## 18.2 推荐最终版

使用：

```text
RANSAC + nonlinear reprojection refinement
```

目标：

\[
X_i^t
=
\arg\min_X
\sum_{c\in V_i^t}
\rho(
\|\pi(P_cX)-p_c\|^2
)
\]

其中：

```text
rho = Huber / Cauchy
```

---

# 19. Triangulation Outlier Removal

假设：

```text
5 cameras
```

其中一个观测错误。

必须能够自动移除。

策略：

1. 初始 RANSAC 两视图采样。
2. 计算所有 camera reprojection error。
3. 保留 inlier cameras。
4. 使用 inlier multi-view refine。

要求：

```text
num_inlier_views >= 2
```

高质量 Track 推荐：

```text
>= 3
```

---

# 20. Step 9：利用已有逐帧稀疏点云验证

对于三角化：

\[
X_i^t
\]

在该帧已有点云：

\[
P_t=\{Q_j\}
\]

寻找最近点：

\[
d_i^t
=
\min_j
\|X_i^t-Q_j\|
\]

这个距离只用于：

```text
confidence / validation
```

不要直接根据最近邻改 Track ID。

---

## 20.1 尺度自适应阈值

不要固定：

```text
0.01 meter
```

建议根据场景尺度或者局部点云 spacing 自动确定：

\[
\tau_{3D}=k\cdot median\_nn\_distance
\]

例如：

```yaml
sparse_verify:
  nn_scale: 3.0
```

---

# 21. Step 10：轨迹运动一致性

三维轨迹：

\[
X_{t-1},X_t,X_{t+1}
\]

速度：

\[
v_t=X_t-X_{t-1}
\]

加速度：

\[
a_t=X_{t+1}-2X_t+X_{t-1}
\]

如果：

\[
\|a_t\|
\]

突然异常，不立即删除，而降低：

```text
motion_confidence
```

---

## 21.1 不要过强平滑

因为后续可能包含：

- 手部快速动作。
- 脚部快速运动。
- 新物体出现。
- 碰撞。
- 突然运动。

因此运动约束是：

```text
soft prior
```

而不是：

```text
hard constraint
```

---

# 22. Track Confidence

每个 Track 每一帧计算：

\[
C_i^t
=
w_1C_{match}
+w_2C_{flow}
+w_3C_{reproj}
+w_4C_{views}
+w_5C_{sparse}
+w_6C_{temporal}
\]

建议全部归一化到：

```text
[0,1]
```

---

## 22.1 Match Confidence

来自：

```text
LightGlue / RoMa
```

---

## 22.2 Flow Confidence

由：

- flow 网络 confidence。
- forward-backward error。
- local consistency。

决定。

---

## 22.3 Reprojection Confidence

\[
C_{reproj}
=
\exp
\left(
-\frac{e_{reproj}^2}
{2\sigma_r^2}
\right)
\]

---

## 22.4 View Confidence

例如：

\[
C_{views}
=
\min
\left(
\frac{N_{views}}{4},
1
\right)
\]

---

## 22.5 Sparse Point Cloud Confidence

\[
C_{sparse}
=
\exp
\left(
-\frac{d_{sparse}^2}
{2\sigma_s^2}
\right)
\]

---

## 22.6 Temporal Confidence

根据：

- 速度变化。
- 加速度变化。
- 历史轨迹长度。
- 是否连续。

决定。

---

# 23. Track State Machine

必须实现生命周期。

推荐：

```text
NEW
 ↓
TENTATIVE
 ↓
ACTIVE
 ↓
OCCLUDED
 ├────────────→ ACTIVE
 ↓
LOST
 ↓
DEAD
```

---

## 23.1 NEW

条件：

- 新检测到跨相机一致 feature。
- 可三角化。
- 不属于已有 Track。

---

## 23.2 TENTATIVE

需要连续验证，例如：

```text
2~3 frames
```

满足：

- 多视角支持。
- 重投影误差合理。
- temporal edge 连续。

才升级：

```text
ACTIVE
```

---

## 23.3 ACTIVE

稳定 Track。

---

## 23.4 OCCLUDED

当前帧无法可靠三角化，但历史 Track 仍可信。

例如：

```text
missing <= 3~5 frames
```

保持 ID。

---

## 23.5 LOST

长时间没有 observation，但仍保留 descriptor / motion state 等用于恢复。

---

## 23.6 DEAD

超过最大 gap 后终止。

---

# 24. Track Recovery

Track 短暂遮挡：

```text
frame 20 ACTIVE
frame 21 OCCLUDED
frame 22 OCCLUDED
frame 23 candidate appears
```

恢复时综合：

```text
descriptor similarity
+
predicted 2D position
+
predicted 3D region
+
multi-camera support
+
reprojection consistency
```

满足条件：

```text
same track_id
```

禁止直接创建新 Track。

---

# 25. 新生 Track

每一帧都检查：

```text
unassigned SpatialGroups
```

如果：

```text
multi-view support >= 2
triangulation valid
reprojection error good
```

生成：

```text
NEW track
```

经过连续 2~3 帧验证后：

```text
ACTIVE
```

这样才能处理：

- 新生表面。
- 物体进入场景。
- 手臂从遮挡后出现。
- 衣服新暴露区域。

---

# 26. Track Merge

可能出现：

```text
Track A
Track B
```

实际上为同一个物理点。

满足：

1. descriptor 长期一致。
2. 时序不冲突。
3. 三维位置连续。
4. observation camera 不冲突。

才允许 merge。

Merge 操作必须保守。

---

# 27. Track Split

如果某 Track 同时关联到两个明显冲突空间 group：

```text
A -> B
A -> C
```

不要强制合并。

应该：

```text
highest confidence -> existing track
second candidate -> tentative/new branch
```

必要时进行 split。

# 37. 静态 / 动态轨迹判断

# 49. Agent 开发原则

# 51. 最终目标

本系统完成后，每个动态或静态真实表面点尽可能具有：

```text
稳定的 Track ID
+
多相机二维 observation
+
每一帧重新计算的 3D position
+
置信度
+
可见性
+
生命周期
```

```text
4DGS static/dynamic separation

newborn-object modeling
```
